# Student Finance Tracker: spec

## Theme

A single page app that helps a student keep track of what they spend. Every purchase is saved as a record with a description, an amount, a category and a date. The app shows where the money goes, warns when a budget cap is passed, and lets the student search their records with regular expressions.

Everything runs in the browser. There is no server and no account. Data is kept in localStorage and can be exported to a JSON file and imported again.

## Who it is for

- A student who wants a quick way to log spending between classes, mostly on a phone
- A student who reviews the month on a laptop and wants to sort and search
- Anyone who uses the keyboard only or a screen reader

## Features

### Records

- Add a record with a form that checks every field while you type
- See records in a table on wide screens and as cards on small screens
- Edit a record in place, Enter saves and Escape cancels
- Delete a record after confirming in a dialog
- Sort by date, description or amount, in both directions

### Search

- Live search using a regular expression
- A bad pattern never crashes the page, it shows an inline message
- Toggle to ignore or respect letter case
- Matching text is highlighted
- Example patterns are shown as hints
- The number of results is announced

### Dashboard

- Total number of records
- Total spent in the display currency
- The category with the highest spend
- A bar chart of the last 7 days
- Remaining budget, or how far over the cap you are

### Settings

- A base currency and two other currencies with manual exchange rates
- Choice of which currency amounts are displayed in
- Budget cap
- Add, rename and remove categories
- Export to JSON, import from JSON with validation, clear all data

### Pages

- index.html: the app
- tests.html: small assertions for the validators, the search helpers and the import checks

## Data model

Every record has the same seven fields.

| Field | Type | Rules |
| --- | --- | --- |
| id | string | `txn_` followed by at least four digits. Generated by the app, unique, never reused after a delete |
| description | string | No leading or trailing spaces. Double spaces are collapsed before saving |
| amount | number | Zero or more, at most two decimal places. Always stored in the base currency |
| category | string | Letters, with single spaces or hyphens between words |
| date | string | `YYYY-MM-DD` and a real calendar date |
| createdAt | string | ISO timestamp set once when the record is created |
| updatedAt | string | ISO timestamp refreshed on every edit |

Example record:

```json
{
  "id": "txn_0001",
  "description": "Lunch at the cafeteria",
  "amount": 4.5,
  "category": "Food",
  "date": "2025-09-29",
  "createdAt": "2025-09-29T12:15:00.000Z",
  "updatedAt": "2025-09-29T12:15:00.000Z"
}
```

### Settings

| Field | Type | Notes |
| --- | --- | --- |
| baseCurrency | string | Three letter code, for example USD |
| otherCurrencies | array | Two entries, each with a `code` and a `rate` (how much one unit of the base currency is worth) |
| displayCurrency | string | One of the three codes above |
| budgetCap | number or null | In the base currency. null means no cap |
| categories | array of strings | Starts as Food, Books, Transport, Entertainment, Fees, Other |
| theme | string or null | light or dark. null follows the system setting |

### Storage

One localStorage key holds a single object:

```json
{ "records": [], "settings": {}, "nextId": 1 }
```

`nextId` only ever goes up, which is how ids stay unique after deletes. If the stored text cannot be parsed or has the wrong shape, the app starts from the sample data and tells the user.

## Accessibility plan

### Landmarks

- `header` with the site title, the main navigation and the theme toggle
- `nav` labelled "Sections"
- `main` holding five labelled `section` elements
- `footer` with contact links

### Heading outline

- h1 Student Finance Tracker
  - h2 About
  - h2 Dashboard
    - h3 Total records, Total spent, Top category, Budget
    - h3 Last 7 days
  - h2 Records
    - h3 one per record card on small screens
  - h2 Add a record
  - h2 Settings
    - h3 Currencies
    - h3 Budget cap
    - h3 Categories
    - h3 Your data

### Focus order

1. Skip to main content link
2. Navigation links, then the theme toggle
3. About links
4. Records: search box, ignore case toggle, sort control, pattern hints, then each record's Edit and Delete
5. Add a record form: description, amount, category, date, Add record, Clear form
6. Settings: currencies, budget cap, categories, data buttons
7. Footer links

Where focus goes after an action:

- After adding a record: back to the description field, ready for the next one
- After saving or cancelling an edit: the Edit button of that record
- After deleting: the Edit button of the next record, or the Records heading if none are left
- After cancelling a dialog: the button that opened it
- After an import: the Records heading

### Live regions

| Region | Type | Used for |
| --- | --- | --- |
| Form summary | role="status" | Result of submitting the add form |
| Search result count | aria-live="polite" | "Showing 3 of 14 records" and the invalid pattern note |
| Records status | role="status" | Saved, deleted, imported |
| Budget, under the cap | aria-live="polite" | Remaining amount |
| Budget, over the cap | aria-live="assertive" | Overage |
| Import error | role="alert" | Why a file was rejected |
| Settings status lines | role="status" | Settings saved, export done |

### Contrast targets

- Body text and labels: at least 4.5:1 against their background, in both themes
- Borders of inputs and buttons, and focus rings: at least 3:1
- Highlighted search matches keep 4.5:1 for the text inside the mark
- Colour is never the only signal: errors have text, sort direction has an arrow and aria-sort

### Motion

New rows fade in and bars grow. Both are switched off when the user asks for reduced motion.
